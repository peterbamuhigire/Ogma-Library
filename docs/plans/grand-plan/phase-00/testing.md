## Golden-corpus harness specification (for Phase 02)

Phase 00 does not instantiate the golden corpus, but it does produce the
**corpus manifest** (P00-WP2-T9 → `docs/testing/GOLDEN-CORPUS-MANIFEST.md`)
that Phase 02 uses as the fixture seed. The manifest must specify:

| Fixture name | Description | Source / license | Hash oracle method |
| --- | --- | --- | --- |
| `gc-simple-text` | Simple single-column PDF, text layer present | Public domain (e.g. Project Gutenberg) | SHA-256 of the PDF bytes |
| `gc-scanned-image` | Scanned image-only PDF, no text layer | Owner-supplied synthetic | SHA-256 |
| `gc-password-protected` | Password-protected PDF (owner knows password) | Owner-supplied synthetic | SHA-256; password stored in test secret |
| `gc-large-1000pp` | 1,000+ page PDF | Public domain document | SHA-256 |
| `gc-two-column` | Two-column academic-style layout | CC-licensed or public domain | SHA-256 |
| `gc-bad-metadata` | PDF with corrupt or missing XMP metadata | Owner-supplied synthetic | SHA-256 |
| `gc-embedded-toc` | PDF with embedded outline/TOC | Public domain | SHA-256 |
| `gc-rotated-pages` | PDF with mixed-rotation pages | Owner-supplied synthetic | SHA-256 |
| `gc-non-english` | French-language PDF (tests i18n of text extraction) | Public domain (e.g. French Gutenberg) | SHA-256 |
| `gc-forms-unusual-fonts` | PDF with form fields and unusual embedded fonts | Owner-supplied synthetic | SHA-256 |
| `gc-perf-500` | Synthetic 500-book library (generated by seed) | Tool-generated | Seed-deterministic hash |
| `gc-perf-2000` | Synthetic 2,000-book library (generated by seed) | Tool-generated | Seed-deterministic hash |

Every file must be:
1. Cleared for inclusion in the test suite (CON-9 verification, P00-WP2-T9).
2. Version-pinned: stored in `tests/golden-corpus/fixtures/` with a
   `MANIFEST.sha256` file listing each filename and its expected SHA-256 hash.
3. Deterministic oracles: every automated test that uses a golden-corpus file
   must assert against the pre-computed hash or a known extracted property (e.g.
   page count, title string, annotation round-trip) — not a floating comparison.

### Performance corpus (synthetic, seed-deterministic)

The `gc-perf-500` and `gc-perf-2000` corpora are generated by a deterministic
seeded tool (Phase 02 harness). The generator takes an integer seed and produces
N book records with realistic metadata distributions, file-name patterns, and
sidecar structures — without requiring real PDF files for the catalogue-layer
performance tests. Real PDF rendering tests use the non-synthetic fixtures.

## Defect classification for Phase 00

All findings from the Phase 00 verification checks are classified as:

- **R5 (functional)**: a missing or incorrect decision entry, an incomplete ADR,
  or a failing governance check. Blocks phase close.
- **R2 (privacy breach)**: a decision in CON-7 or ADR-0007 that would allow
  off-device data transmission without consent. Blocks phase close as unwaivable.
- **R1 (data loss)**: not expected in a documentation phase; any discovered
  risk to user data must be recorded as a tracked item for Phase 04+.

No R1 or R2 defects may be open when Phase 00 closes.
