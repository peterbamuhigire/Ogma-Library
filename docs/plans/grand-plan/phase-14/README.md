# Phase 14 — 3D Bookshelf

Single mission: ship a WebGL2 / Three.js 3D bookshelf hosted in a platform WebView
(WebView2 on Windows, WKWebView on macOS) at 60 FPS for 500 books, behind a
typed C#↔JS message bridge and `ogma://` asset scheme, with a first-class
accessible grid/list fallback when WebGL2 is absent.

---

## 1. Title & one-line mission

**Phase 14 — 3D Bookshelf**

Deliver the signature 3D bookshelf experience: a WebView-hosted Three.js scene
driven by a validated, typed C#↔JS bridge, spine textures generated by SkiaSharp,
≥ 60 FPS at 500 books, and a first-class accessible fallback for every path where
WebGL2 is unavailable.

## 3. Objectives

1. **60 FPS for 500 books.** The Three.js scene renders ≥ 60 FPS at 500 spine-
   textured book objects on the Phase 00 reference hardware (NFR-OGMA-006); CI
   performance fixture asserts the budget.
2. **Typed, validated bridge.** Every C#→JS message and every JS→C# message is a
   discriminated-union type; inbound messages (bookClicked, bookDoubleClicked,
   bookHovered, cameraChanged) are validated before any handler is invoked (SI-3).
3. **`ogma://` asset scheme enforced.** Spine and cover textures are served via a
   custom `ogma://` scheme handler registered in both WebView2 and WKWebView; no
   raw `file://` or UNC paths reach the WebView (security: path traversal
   prevention, SI-3 extension).
4. **Accessible first-class fallback.** When WebGL2 capability check fails (or the
   user disables 3D via settings), the grid view is shown with no capability
   degradation; every catalogue capability remains reachable from the fallback
   (principles 5, 6).
5. **Book-detail parity.** Clicking or double-clicking a spine in the 3D shelf
   navigates to the exact same book-detail route used by grid, list, and directory
   views (FR-CAT-001: all four views open the same book-detail).
6. **Keyboard focus across the native↔WebView boundary.** The user can Tab into
   the 3D shelf, navigate between books with arrow keys, and press Enter to open a
   book — all without a mouse (WCAG 2.2 AA).
7. **WebView2/WKWebView divergence is abstracted.** A `IWebViewBridge` interface
   hides platform-specific WebView initialization, scheme registration, and message
   dispatch; the scene and ViewModel code is platform-agnostic.

## 4. Scope

### In scope

- `IWebViewBridge` interface and two implementations:
  `WebView2Bridge` (Windows, requires WebView2 runtime) and
  `WKWebViewBridge` (macOS, built-in).
- `ogma://` custom URI scheme handler: serves spine textures, cover images, and
  the Three.js bundle from the app's sidecar asset directory; validates paths
  against the library root (no traversal).
- Typed C#↔JS bridge message types (TypeScript enums + C# records):
  - **Outbound (C#→JS):** `SetScene`, `UpdateBook`, `RemoveBook`, `SetCamera`,
    `SetTheme`, `SetLayout`.
  - **Inbound (JS→C#):** `BookClicked`, `BookDoubleClicked`, `BookHovered`,
    `CameraChanged` — all validated before dispatch.
- Three.js scene (`src/shelf3d/`): book objects with SkiaSharp-rendered spine
  textures; instanced mesh for performance; two layout modes (shelf-row, grid-3D).
- Spine texture generation via SkiaSharp: title + author + dominant-color
  background; cached to sidecar `spines/` folder; served via `ogma://`.
- `Bookshelf3DViewModel`: scene model builder from catalogue; selected-book
  navigation; layout/camera commands.
- `Bookshelf3DView` Avalonia: hosts the WebView via `NativeControlHost`;
  keyboard focus management; fallback overlay.
- WebGL2 capability check on scene init; automatic fallback trigger when absent.
- Camera controls (orbit, zoom, pan) in Three.js; `CameraChanged` fires on
  significant change to allow C# to persist camera state.
- Theme sync: light/dark Avalonia theme communicated to Three.js via `SetTheme`
  message.
- Architecture test: `Bookshelf3D_HasNo_DirectDependency_On_CatalogueIdentity`
  (3D bounded context reads through contracts only).
- All strings en + fr; icon manifest for this phase.

### Explicitly out of scope

- OCR, password PDF, or split-view (Phase 15).
- AI recommendations displayed in the 3D shelf (post-V1 feature).
- Annotation or bookmark overlays in 3D (post-V1).
- The Three.js scene running without WebView (no custom renderer); WebView is
  the mandated host per ADR-0003.
- Linux (bonus, not MVP gate; noted in CON-6 context gap).

## 7. Architecture & approach

### 7.1 Bounded contexts touched

- **Bookshelf Presentation** (primary — `Bookshelf3D` project).
- **Catalogue** (read-only: book identities, titles, authors, cover/spine URLs).
- **Settings & Security** (`ogma://` scheme handler; camera state persistence).

### 7.2 WebView host abstraction

```
IWebViewBridge
  ├── InitializeAsync(IWebViewContainer host) -> Task
  ├── PostMessageAsync(OutboundMessage msg) -> Task        // C# -> JS
  ├── event Action<InboundMessage> MessageReceived          // JS -> C#
  ├── RegisterSchemeHandlerAsync(string scheme, ISchemeHandler handler)
  └── ExecuteScriptAsync(string js) -> Task<string>

WebView2Bridge (Windows)
  — wraps Microsoft.Web.WebView2.Avalonia
  — registers ogma:// via CoreWebView2.WebResourceRequested

WKWebViewBridge (macOS)
  — wraps Avalonia.WebView or a custom NSView binding
  — registers ogma:// via WKURLSchemeHandler
```

`IWebViewBridge` is registered in DI per platform in the composition root.
The `Bookshelf3DViewModel` and `Bookshelf3DView` are platform-agnostic.

### 7.3 Typed message bridge

All messages are sealed C# records and matching TypeScript types generated from
the same source-of-truth JSON schema at build time (a `T4` template or a
`dotnet-script` tool in the build pipeline):

**Outbound (C#→JS, serialized as JSON):**

```csharp
// Discriminated union via abstract base:
abstract record OutboundMessage(string Type);
record SetScene(BookSceneItem[] Books, CameraState Camera) : OutboundMessage("SetScene");
record UpdateBook(string BookId, BookSceneItem Book) : OutboundMessage("UpdateBook");
record RemoveBook(string BookId) : OutboundMessage("RemoveBook");
record SetCamera(CameraState Camera) : OutboundMessage("SetCamera");
record SetTheme(string ThemeKey) : OutboundMessage("SetTheme");  // "light" | "dark"
record SetLayout(string Layout) : OutboundMessage("SetLayout");  // "shelf" | "grid3d"
```

**Inbound (JS→C#, validated before dispatch):**

```csharp
abstract record InboundMessage(string Type);
record BookClicked(string BookId) : InboundMessage("BookClicked");
record BookDoubleClicked(string BookId) : InboundMessage("BookDoubleClicked");
record BookHovered(string BookId) : InboundMessage("BookHovered");
record CameraChanged(CameraState Camera) : InboundMessage("CameraChanged");
```

Validation: `InboundMessageValidator.Validate(InboundMessage)` checks:
- `BookId` is non-null, non-empty, and matches the regex `^[0-9a-f-]{36}$` (GUID format).
- `CameraState` values are finite floats within scene bounds.
- Any unknown `Type` field is logged and discarded (no exception propagated to JS).

SI-3: any inbound message that fails validation is rejected; the corresponding
domain action is not triggered; the failure is written to the local diagnostic log.

### 7.4 `ogma://` asset scheme

The `ogma://` URI format: `ogma://assets/<asset-class>/<encoded-filename>`

- `<asset-class>` is one of: `covers`, `spines`, `thumbnails`.
- `<encoded-filename>` is a percent-encoded filename (no directory separators).
- The scheme handler resolves the filename against the sidecar asset directory
  (`{AppData}/Ogma/assets/<asset-class>/`); it performs a strict path-containment
  check: the resolved absolute path must start with the sidecar root — any path
  traversal attempt returns HTTP 403 (not a 404, so the caller knows it was
  deliberate).
- Raw `file://` URIs and UNC paths (`\\server\share`) are **never** constructed
  or passed to the WebView.
- The `SchemeHandlerTest_PathTraversal_Returns403` integration test covers this.

### 7.5 Spine texture generation

`SpineTextureGenerator` (SkiaSharp):
- Input: `BookId`, title string, author string, dominant cover color (extracted
  by Phase 05 thumbnail job).
- Output: 128×512 px PNG written to sidecar `spines/<bookId>.png`.
- Typography: title (bold, max 2 lines, truncated with ellipsis), author (regular,
  1 line), white/dark text chosen for contrast against dominant color.
- Called as a background job (Phase 05 job infrastructure) during ingestion; lazy
  generation when first needed by the 3D view.
- Cache invalidation: regenerate when title/author/dominant-color changes.

### 7.6 Three.js scene (TypeScript, `src/shelf3d/`)

- **InstancedMesh:** all book objects share geometry and material; per-instance
  spine texture applied via a texture atlas or per-instance material swap for
  500-book budget.
- **60 FPS budget:** target 16.67 ms frame budget; texture atlas packing preferred
  over per-instance texture switches (benchmark in WP5).
- **Layouts:** `shelf` (rows of books at realistic proportions) and `grid3d`
  (isometric-style grid).
- **Interaction:** `raycaster` on pointer events; fires `BookClicked` /
  `BookHovered` through the bridge.
- **Keyboard navigation:** the Three.js scene registers `keydown` on the WebView
  document; arrow keys move a "focus cursor" between books; Enter fires
  `BookDoubleClicked`. The native Avalonia view sets `TabIndex` to enter the
  WebView container; Tab goes in, Shift-Tab comes out.
- **Theme:** `SetTheme` message updates scene background and ambient light.
- **Camera:** orbit controls (Three.js `OrbitControls`); `CameraChanged` fires
  on significant change (throttled to ≤ 1 Hz to avoid bridge flooding).

### 7.7 WebGL2 capability check and fallback

On `InitializeAsync`:
1. Execute JS: `return !!document.createElement('canvas').getContext('webgl2');`
2. If `false` (or if the bridge throws within 2 seconds): set
   `Bookshelf3DViewModel.IsWebGl2Supported = false`; the view switches to the
   grid-view fallback with an informational banner: "3D view is not available on
   this device — showing grid view."
3. The user can also manually disable 3D in Settings; this also triggers the
   fallback permanently.
4. The fallback view exposes the full catalogue: filter, sort, virtual shelves,
   bulk edit, book-detail navigation — no feature loss (principle 5).

### 7.8 Cross-platform notes

| Concern | Windows (WebView2) | macOS (WKWebView) |
| --- | --- | --- |
| WebView2 runtime | Bundled with MSIX / or detected at startup | N/A — WKWebView is system-provided |
| `ogma://` registration | `CoreWebView2.AddWebResourceRequestedFilter` + event | `WKURLSchemeHandler` protocol implementation |
| JS→C# message | `CoreWebView2.WebMessageReceived` | `WKScriptMessageHandler` via `userContentController` |
| C#→JS message | `PostWebMessageAsJsonAsync` | `evaluateJavaScript:completionHandler:` |
| WebGL2 availability | Chrome-based; WebGL2 generally available | WebKit; WebGL2 available from macOS 12+; check at runtime |
| Thread affinity | `CoreWebView2` must be used on the UI thread | All WebKit calls on main thread; dispatch accordingly |
| Frame rate monitoring | DevTools protocol (optional) | `CADisplayLink`-style approach via JS `requestAnimationFrame` |

Both platforms are tested in CI. macOS WKWebView does not support `file://` for
cross-origin requests — `ogma://` is the solution here, not just a security choice.

### 7.9 Keyboard focus boundary

- Avalonia `Bookshelf3DView` sets `IsTabStop = true` on the `NativeControlHost`.
- On Tab-in: sends `SetFocus` JS call to the Three.js scene.
- On Tab-out (Shift-Tab from first or Tab from last book): restores Avalonia focus
  to the next/previous native control via a `FocusHelper`.
- A screen-reader virtual cursor cannot enter the WebView; therefore the
  accessible fallback (grid view) must be reachable without ever entering 3D.
  The SR walkthrough test confirms this (Phase 21 full audit; Phase 14 unit test).

## 13. Risks

| Risk | Tier | Mitigation |
| --- | --- | --- |
| WKWebView WebGL2 unavailable on older macOS targets | R3 | Capability check at runtime; fallback triggered; minimum macOS version confirmed in Phase 00 context gap; document in ADR-0003 |
| WebView2 runtime not present on end-user Windows machine | R3 | Detect at startup; show actionable install prompt; bundling strategy in Phase 22 MSIX |
| 60 FPS target not met with per-instance textures | R3 | InstancedMesh + texture atlas design; benchmark in WP9; if budget missed, reduce atlas quality or implement LOD for distant books |
| JS→C# message bridge latency causes interaction lag | R5 | Throttle `CameraChanged`; `BookHovered` is fire-and-forget; `BookClicked` path is latency-sensitive — benchmark round-trip < 50 ms |
| Path traversal in `ogma://` handler | R2 | Strict containment check in WP2; dedicated integration test; code review |
| Cross-origin CORS rejection in WebKit for `ogma://` | R5 | `ogma://` is a fully custom scheme; WKURLSchemeHandler owns it entirely; no CORS headers needed; tested in Phase 01 spike |
| Phase 01 spike (G1) not retired before Phase 14 starts | R3 | Phase 14 start is gated on G1; if spike fails, ADR-0003 is amended and an alternative is evaluated |
