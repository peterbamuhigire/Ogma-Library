# Phase 22 — Packaging, Signing & Store Submission

One sentence: Build, sign, notarize, and publish Ogma Library to all four
distribution targets — GitHub Releases, Velopack direct feeds, the Microsoft
(Windows) Store, and the Mac App Store — with a signed, reversible, verifiable
auto-update trust chain on both platforms.

## 2. Objectives

1. The signed, notarized, installable application is built from a single CI
   pipeline on both Windows and macOS runners; the build is reproducible and
   channel-tagged (Dev / Alpha / Beta / Stable) with a promote-not-rebuild policy.
2. Velopack direct feeds (full + delta) are operational on both platforms with
   four channels (Dev, Alpha, Beta, Stable); the update trust chain is verified:
   the build artifact is signed, the feed descriptor is signed, and the client
   verifies both independently of transport (CTRL-OGMA-012/013).
3. The MSIX package is submitted to and accepted by the Microsoft (Windows) Store;
   an enterprise group-policy deployment path is documented and tested.
4. The Developer-ID-signed and Apple-notarized DMG is available on GitHub
   Releases; macOS Gatekeeper passes silently on the reference machine.
5. The Mac App Store build is submitted and accepted; the App Store sandbox and
   entitlement implications for a local-file-reading app are explicitly
   addressed (documented in ADR-0021) and verified by the review submission.
6. All reversible migrations are verified: backup-before-apply runs before any
   schema migration; rollback is tested for all schema version pairs in scope;
   no migration is irreversible.
7. Code-signing key custody is documented (HSM or equivalent); key rotation
   procedure is recorded in a runbook.

## 3. Scope

### In scope

- **CI release pipeline:**
  A single `release.yml` GitHub Actions workflow that:
  1. Restores, builds, and tests the solution on both platforms.
  2. Publishes platform-specific self-contained builds.
  3. Signs binaries (Windows: Authenticode via `SignTool`; macOS: `codesign`
     with Developer ID certificate) using secrets stored in GitHub Actions
     Encrypted Secrets (or an HSM-backed signing service).
  4. Notarizes the macOS artifact via `xcrun notarytool`.
  5. Packages: Velopack (both platforms), MSIX (Windows), DMG (macOS).
  6. Signs the Velopack feed descriptor (Ed25519 signing key, per ADR-0009).
  7. Publishes to GitHub Releases and uploads Velopack feed artifacts.
  - The pipeline is channel-aware: a `channel` input parameter tags the artifact
    and determines the feed URL. Channels: `dev`, `alpha`, `beta`, `stable`.
    Promoting a build from `alpha` to `beta` re-signs the feed descriptor;
    it does not rebuild the binary.

- **Velopack direct feeds (both platforms):**
  - Full package + delta package generated by `vpk pack`.
  - Feed hosted on GitHub Releases (or a static CDN if the owner decides):
    `releases-<channel>.json` descriptor signed with the Ed25519 private key.
  - Client verifies descriptor signature before applying any update
    (CTRL-OGMA-012); verifies binary hash after download (CTRL-OGMA-013).
  - Delta update tested: install version N, apply delta to N+1; confirm
    post-update binary is byte-for-byte identical to a fresh N+1 install.

- **MSIX + Microsoft (Windows) Store:**
  - MSIX package produced by the CI pipeline; signing with a Windows Store
    certificate (or a Developer certificate for sideloading / enterprise).
  - Microsoft Store submission: `Package.appxmanifest` configured with the
    correct Publisher, display name, capabilities (local file access, no
    inbound network listener in standalone mode), and version.
  - Windows Store submission via Partner Center; review pass expected; submission
    record and review correspondence documented in `docs/distribution/WINDOWS-STORE.md`.
  - Enterprise group-policy deployment: MSIX sideloading via `AppInstaller`
    URI or an Intune deployment package; procedure documented in
    `docs/distribution/ENTERPRISE-DEPLOY.md`.

- **Developer-ID-signed + notarized DMG:**
  - macOS `codesign --deep --options runtime` with Hardened Runtime; entitlements:
    `com.apple.security.files.user-selected.read-write` (for the user-chosen
    library root) and `com.apple.security.network.client` (for AI gateway calls
    on opt-in only). No `com.apple.security.files.all` (least privilege).
  - `xcrun notarytool submit` → Apple notarization service → `xcrun stapler staple`.
  - Gatekeeper verification: `spctl -a -t exec -vv Ogma\ Library.app` passes.
  - DMG published to GitHub Releases with checksum (SHA-256) file.

- **Mac App Store submission (ADR-0021 constraints):**
  - The Mac App Store requires the App Sandbox (`com.apple.security.app-sandbox`).
    This is a significant constraint for a local-file-reading app. The App
    Sandbox limits access to the file system to:
    - Files the user explicitly opens via `NSOpenPanel` (sandbox bookmark).
    - The app's container directory.
  - **Implication for Ogma Library:** The library root must be accessed via a
    security-scoped bookmark persisted in `UserDefaults` (or the SQLite
    catalogue). The current `IFileSystemService` implementation must be adapted
    to resolve the bookmark before any file operation in the MAS build.
    This is the most significant engineering task in Phase 22. It is isolated
    to the MAS build target via a compiler directive (`#if APPSTORE`).
  - **Entitlements for MAS build:**
    - `com.apple.security.app-sandbox = true`
    - `com.apple.security.files.user-selected.read-write` (security-scoped bookmark)
    - `com.apple.security.network.client` (AI gateway)
    - No `com.apple.security.files.all`; no `com.apple.security.network.server`
      (the MAS build does not support LAN Host mode; this is called out in the
      MAS build's Settings as "LAN Host not available in the Mac App Store build;
      use the direct download for full LAN features").
  - **ADR-0021:** Records the MAS sandbox constraint, the security-scoped
    bookmark approach, the LAN Host limitation in MAS builds, and the
    decision to maintain two macOS build targets (MAS + direct DMG).
  - MAS submission via App Store Connect; review pass expected; review
    correspondence documented in `docs/distribution/MAC-APP-STORE.md`.

- **Signed update trust chain (CTRL-OGMA-012/013):**
  - **CTRL-OGMA-012:** Build artifact is signed (Authenticode / Developer ID)
    before the Velopack package is created.
  - **CTRL-OGMA-013:** Velopack feed descriptor (`releases-<channel>.json`) is
    signed with the Ed25519 private key; the client verifies the descriptor
    signature on every update check, independently of transport (HTTPS is defense
    in depth, not the sole trust anchor).
  - Key custody: the Ed25519 signing private key is stored in a GitHub Actions
    Environment Secret (environment = `release`); only the release pipeline
    has access. The procedure for rotating the key is documented in
    `docs/distribution/KEY-CUSTODY.md`.
  - HSM path: if the owner procures a hardware security module (YubiKey HSM
    or equivalent), the signing key can be moved there; `KEY-CUSTODY.md`
    documents both the secrets-based and HSM-based paths.

- **Reversible migrations verification:**
  - For every EF Core schema migration introduced in Phases 04–20, verify:
    1. `ogma_db_backup_<version>.sqlite` is created before `migrate` runs.
    2. The backup is valid (SHA-256 matches the pre-migration catalogue).
    3. If migration fails, `migrate --rollback` restores from backup without
       data loss.
  - Migration rollback test matrix: test rolling back from each version to
    the prior version; all user-created data (books, annotations, shelves,
    reading progress) must survive.

- **Public GitHub Releases:**
  - GitHub Release created per channel promotion; assets: Windows installer
    (MSIX), Windows direct (Velopack exe), macOS DMG (direct + notarized),
    checksums file (SHA-256), and CHANGELOG.md excerpt.
  - Release notes generated from `CHANGELOG.md` (Phase 20 `changelog-automation`
    skill keeps this current).

### Explicitly out of scope

- LAN Host mode in the MAS build (explicitly excluded — see ADR-0021).
- Linux packaging (bonus; not a release gate).
- Cloud / CDN infrastructure for Velopack feeds beyond GitHub Releases
  (the owner may add a CDN later; the feed URL is configurable and abstracted
  behind a setting).
- Store listing screenshots and promotional artwork (drafted here for
  submission, but creative production is an Owner ask — see §13).
- Post-launch telemetry infrastructure (Phase 23).

## 6. Architecture & approach

### Bounded contexts touched

- **Packaging & Updates** (primary): the Velopack update check, descriptor
  verification, and apply-migration logic live here.
- **Settings & Security**: MAS security-scoped bookmark persistence;
  LAN-Host-unavailable notice in MAS build.
- **Application** (read-only): `IUpdateService` interface and its
  `VelopackUpdateService` implementation.

### Build targets

Two macOS build targets:

| Target | Identifier | Entitlements | Distribution |
| --- | --- | --- | --- |
| `macOS-direct` | `com.chwezicore.ogmalibrary` | `user-selected.read-write`, `network.client` | GitHub Releases, Velopack |
| `macOS-mas` | `com.chwezicore.ogmalibrary` | Same + `app-sandbox = true` | Mac App Store |

`#if APPSTORE` compiler directive gates the security-scoped bookmark code path
in `IFileSystemService` and the "LAN Host not available" notice in Settings.

### Update trust chain implementation

```
┌──────────────────────────────────────────────────────────────────┐
│  Release CI pipeline                                             │
│  1. Build + test                                                 │
│  2. Sign binary (Authenticode / Developer-ID) ─────► CTRL-012   │
│  3. vpk pack → full.nupkg + delta.nupkg                         │
│  4. Sign releases-<channel>.json (Ed25519) ─────────► CTRL-013  │
│  5. Upload to GitHub Releases                                    │
└──────────────────────────────────────────────────────────────────┘
           │
           ▼ (at runtime, on user machine)
┌──────────────────────────────────────────────────────────────────┐
│  VelopackUpdateService.CheckForUpdateAsync()                     │
│  1. Fetch releases-<channel>.json over HTTPS                     │
│  2. Verify Ed25519 signature on descriptor ─────────► CTRL-013  │
│  3. If valid + newer version available: notify user              │
│  4. User confirms update                                         │
│  5. Download artifact                                            │
│  6. Verify Authenticode / Developer-ID signature ──► CTRL-012   │
│  7. Backup catalogue (reversible migration)                      │
│  8. Apply update                                                 │
└──────────────────────────────────────────────────────────────────┘
```

### Migration rollback design

Before `migrate` runs:
```
1. ogma_db_backup_<schema-version>.sqlite = VACUUM INTO backup path
2. sha256sum(backup) stored in AppSettings
3. migrate runs
4. On failure: VACUUM INTO restore path; verify sha256; replace catalogue
```

### Cross-platform CI pipeline

```yaml
# .github/workflows/release.yml (structure)
jobs:
  build-windows:
    runs-on: windows-latest
    steps: [checkout, setup-dotnet, restore, build, test, publish, sign-authenticode,
            pack-velopack, pack-msix, sign-feed-descriptor, upload-artifacts]

  build-macos-direct:
    runs-on: macos-latest
    steps: [checkout, setup-dotnet, restore, build, test, publish, codesign,
            notarize, staple, pack-velopack, pack-dmg, sign-feed-descriptor,
            upload-artifacts]

  build-macos-mas:
    runs-on: macos-latest
    steps: [checkout, setup-dotnet, restore, build -p:AppStore=true, test,
            publish, codesign-mas, pack-pkg, upload-mas-artifact]

  create-release:
    needs: [build-windows, build-macos-direct]
    steps: [download-artifacts, create-github-release, upload-assets,
            upload-velopack-feed]
```

### macOS App Sandbox: security-scoped bookmarks

The user selects the library root via `NSOpenPanel` (Avalonia's
`StorageProvider.OpenFolderPickerAsync`). The `IFileSystemService` implementation
for the MAS build resolves the returned `IStorageFolder` as a security-scoped
bookmark via:

```csharp
// MAS-only implementation (AppStore build target)
public class SandboxedFileSystemService : IFileSystemService
{
    private readonly IBookmarkStore _bookmarkStore;

    public async Task<IDisposable> AcquireAccessAsync(string path)
    {
        var bookmark = await _bookmarkStore.ResolveAsync(path);
        return bookmark.StartAccessingSecurityScopedResource();
        // Dispose() calls StopAccessingSecurityScopedResource()
    }
}
```

`IBookmarkStore` persists the bookmark blob in the SQLite catalogue
(`AppSettings.LibraryRootBookmark`). This is the MAS-specific database column
added in a migration guarded by `#if APPSTORE`.

## 12. Risks

| Risk | Tier | Mitigation |
| --- | --- | --- |
| Mac App Store review rejection due to file-access entitlements | R3 | ADR-0021 is pre-work: confirms the security-scoped bookmark approach before submission. Review `app-store-review` skill checklist before submitting. Prepare a review response template explaining the local-file-reading use case and the user-selected folder model. |
| Windows Store review rejection due to capabilities declaration | R3 | Validate `Package.appxmanifest` against the Store requirements checklist before submission. The app does not open inbound network listeners in standalone mode (CI-2); declare only `internetClient` (for AI gateway, optional) and `removableStorage` / `broadFileSystemAccess` (if needed — prefer user-selected folder instead). |
| Ed25519 signing key compromise | R1 | Document immediate response in `KEY-CUSTODY.md`: revoke old key, generate new key, re-sign all feed descriptors, push new public key via an authenticated out-of-band channel, notify users via the app's update notification surface. Phase 23 runbook covers this scenario. |
| Delta update corrupts installation on edge-case version gap | R3 | Test delta from N-2 to N (not just N to N+1); if unstable, fall back to full-package-only updates for cross-version gaps. |
| MAS sandbox prevents reading user's existing PDF folder on first launch | R3 | The library root picker (`NSOpenPanel`) must be the first action in the MAS onboarding flow; the picker grants the sandbox permission and the bookmark is immediately persisted. Test on a clean MAS sandbox environment before submission. |
| Notarization takes >24 hours (Apple server delay) | R5 | Pipeline waits up to 4 hours polling; if not complete, the job fails and must be re-run manually. Notarize the release candidate 2 business days before the intended GitHub Release date. |
