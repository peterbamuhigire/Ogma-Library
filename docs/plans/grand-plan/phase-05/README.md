# Phase 05 — Ingestion Pipeline & Scanning

Reliably discover, identify, and register every PDF in a library root — without
blocking the UI, without losing user data when files move or disappear, and with
enough diagnostic visibility that the user always knows the health of the scan.

---

## 1. Title & one-line mission

**Phase 05 — Ingestion Pipeline & Scanning.**
Build the background ingestion pipeline that transforms a folder of PDFs into a
fully-populated catalogue: recursive discovery, stable five-tier identity matching,
unavailable-file flagging, resumable idempotent background jobs, SkiaSharp
thumbnail and spine generation, incremental rescan, and a V1 scan health report —
all satisfying FR-LIB-001 through FR-LIB-007.

## 3. Objectives

When this phase is done, all of the following are true:

1. A user can select a folder as the library root (FR-LIB-001); the path is stored
   and persisted; the user can re-select or rescan at any time.
2. Recursive PDF discovery honors a configurable excluded-folder list (FR-LIB-002),
   runs in the background, and reports progress without blocking the UI
   (NFR-PROD-005, < 100 ms UI stall).
3. Each discovered PDF is matched against the catalogue using the five-tier identity
   chain from Phase 04 (FR-LIB-003); renamed or moved files are re-matched without
   creating duplicates.
4. Files that have been removed from disk are flagged `Unavailable` without deleting
   any user data (annotations, progress, bookmarks) from the catalogue (FR-LIB-004).
5. Cover, thumbnail, and spine assets are generated by SkiaSharp background jobs
   (FR-LIB-005); per-file failures are recorded in the `Jobs` table, visible to
   the user, and individually retryable.
6. Incremental rescan skips files whose size and mtime are unchanged since the last
   successful scan (FR-LIB-006), making repeated scans fast.
7. A V1 scan health report surfaces failed files, password-protected PDFs,
   unsupported formats, missing thumbnails, and metadata gaps (FR-LIB-007) in a
   dedicated UI panel.
8. All background jobs are resumable and idempotent (NFR-OGMA-009): restarting the
   app after an interrupted scan continues where it left off with no duplicate work.

## 4. Scope

### In scope

- `ILibraryRootService`: select, store (in `Settings` or `LibraryRoot` catalogue
  record), validate, and return the configured library root path.
- Excluded-folder list: persisted in settings; UI to add/remove entries (Phase 06
  Settings panel — this phase builds the service and the `Jobs` integration).
- `IDiscoveryService`: recursive `Directory.EnumerateFiles("*.pdf", SearchOption.AllDirectories)`
  honoring excluded folders; emits `FileDiscoveredEvent` per file.
- `IIngestionOrchestrator`: coordinates discovery → identity → metadata extraction →
  asset generation; creates and updates `Job` rows; enforces idempotency via
  `IdempotencyKey`.
- `BookIngestionWorker` (BackgroundService in `Workers` project): processes the
  `Jobs` queue; per-file isolation (one job failure does not cancel sibling jobs);
  cancellation-safe.
- `IIdentityMatcher`: thin wrapper over Phase 04 `IBookIdentityService`; updates
  `BookFiles.FileStatus` and `Books.Status`.
- `IUnavailableFileFlagService`: on rescan, marks files not found on disk as
  `FileStatus.Missing`; `Books.Status` → `Unavailable`; user data (annotations,
  progress, bookmarks) untouched.
- `IThumbnailService` + `ISpineService` backed by SkiaSharp: generate cover JPEG
  (200x300), per-page thumbnail (160x220), and spine strip (7x100) and write to
  sidecar via `SidecarService`; runs in `Workers`; never on UI thread.
- `IMetadataExtractionService`: extract `Title`, `Author`, `Subject`,
  `CreationDate` from PdfPig `DocInfo` and XMP; populate `BookMetadataFields`
  with `Source="PDF"`, `Confidence=0.5`.
- `IScanProgressService` + `ScanProgressViewModel`: real-time scan progress
  (files discovered, queued, completed, failed); bound to a UI progress panel.
- Scan progress UI panel: toolbar/status-bar component showing scan phase
  (Discovering / Processing / Generating thumbnails / Complete / Partial failure)
  with progress bar, file count, and failure count; cancel button.
- Incremental rescan: compare `size + mtime` against `BookFiles` record;
  skip re-hashing if unchanged; re-queue only changed/new/missing files.
- V1 scan health report UI panel: tabbed view of failed jobs, password-protected
  files, unsupported formats, missing thumbnails, metadata gaps; retry-all and
  per-item retry actions.
- `Jobs` table integration: every background task is a row with `IdempotencyKey`,
  `Status`, `RetryCount`, and `ErrorMessage`; `JobRecoveryService` at startup
  requeues all `Status=Running` jobs (crash recovery).
- Performance gate: processing 2,000 PDFs with no thumbnails to regenerate
  (incremental rescan, all cached) completes in < 10 s wall-clock
  (NFR-PROD-005 / NFR-OGMA-002 precondition).
- All UI strings externalized and present in `en` + `fr`.
- Colorful icons for scan-related toolbar actions and health-report surfaces
  (see `icons.md`).

### Explicitly out of scope

- Full-text extraction (ExtractedPages / SearchChunks population) — Phase 10.
- ISBN detection and metadata enrichment from providers — Phase 07.
- OCR pipeline — Phase 15.
- Password-protected PDF unlock — Phase 15 (FR-READ-009).
- LAN sharing of scan results — Phases 16-18.
- Settings panel UI (excluded folders list) — Phase 06 builds the settings view;
  this phase provides the service and `Jobs` integration only.

## 7. Architecture & approach

### Bounded contexts touched

**Ingestion Pipeline** (owns this phase). Library Catalogue context (writes
`Books`, `BookFiles`, `BookMetadataFields`, `Jobs`, `AuditEvents` via
`CatalogueDbContext`). Bookshelf Presentation and Reader contexts are consumers
only — they do not write catalogue data.

### Pipeline stages and threading model

```
[UI: Select Root]
      |
      v
DiscoveryService (Task, thread pool)
      | FileDiscoveredEvent (channel)
      v
IdentityMatcher (Task, thread pool)
      | BookMatchResult
      v
MetadataExtractionService (PdfPig, thread pool)
      | BookMetadataFields
      v
Jobs table insert (idempotent, via IdempotencyKey)
      |
      +------> AssetGenerationWorker (SkiaSharp, dedicated worker thread)
      |            ThumbnailService / SpineService
      |
      v
IScanProgressService.Update() (Dispatcher.UIThread.Post for Avalonia)
```

All inter-stage communication uses `System.Threading.Channels.Channel<T>`
(bounded, back-pressure aware). The UI is never awaited on the worker path
(NFR-PROD-005). Avalonia `Dispatcher.UIThread.Post` is the only bridge back to
the UI thread.

### Job idempotency and recovery

- Every ingestible file produces a `Job` row with `IdempotencyKey = SHA256(LibraryRootId + RelativePath)`.
- At startup, `JobRecoveryService.RecoverAsync()` queries `Jobs WHERE Status = 'Running'`
  and re-enqueues them with `RetryCount + 1`. This is the single recovery path
  (NFR-OGMA-009).
- Per-file isolation: each job is executed in a `try/catch`; an exception updates
  `Job.Status = Failed`, `Job.ErrorMessage`; the worker continues to the next job.

### Unavailable-file flagging (FR-LIB-004)

During rescan, `IUnavailableFileFlagService` performs:
1. Load all `BookFiles WHERE FileStatus = Present` for this library root.
2. For each, check `File.Exists(AbsolutePath)`.
3. If missing: set `BookFile.FileStatus = Missing`, `Book.Status = Unavailable`,
   write `AuditEvent(EventType = "BookMarkedUnavailable")`.
4. User data (`Annotations`, `ReadingProgress`, `Bookmarks`) is never touched.
5. If the file re-appears on the next scan, the identity matcher re-matches it,
   sets `FileStatus = Present`, `Book.Status = Active`.

### SkiaSharp thumbnail/spine generation (FR-LIB-005)

- PDFium renders page 0 at 144 DPI → `SKBitmap`; SkiaSharp encodes to JPEG 85%.
- Cover: resize to 200x300 px maintaining aspect ratio with letterboxing.
- Per-page thumbnail: resize to 160x220 px (stored only for pages 0 and the last
  annotated page in Phase 05; all pages on demand in Phase 08).
- Spine strip: render page 0 at 7 px wide × 100 px tall; used by 3D shelf (Phase 14).
- Output written via `SidecarService.Resolve(bookId, SidecarClass.Cover)`.

### Incremental rescan (FR-LIB-006)

- On rescan, `DiscoveryService` emits each discovered file.
- `IdentityMatcher` checks: `BookFiles WHERE RelativePath = ? AND SizeBytes = ? AND MtimeTicks = ?`.
- If unchanged → skip all stages; update `BookFile.LastSeenUtc` only.
- If changed → re-run the full pipeline for that file.
- Deleted files are flagged by `UnavailableFileFlagService` (see above).

### Scan progress UI (minimal surface, Phase 05)

- `ScanProgressViewModel` with properties: `Phase` (string, localized),
  `FilesDiscovered`, `FilesQueued`, `FilesCompleted`, `FilesFailed`,
  `ProgressPct` (0.0-1.0), `IsCancellable`.
- `ScanProgressView`: narrow status bar at the bottom of the main window, plus
  an expandable progress sheet; single `Cancel` button.
- Icon: `ic_scan_library` (oak-amber) in the toolbar; `ic_scan_error` (clay) on
  failure count chip.

### V1 scan health report (FR-LIB-007)

- A dedicated panel (accessible from the library toolbar and from the status bar
  failure chip) with tabs:
  - **Failed jobs** (ErrorMessage, file path, timestamp, Retry / Remove buttons).
  - **Password-protected** (file path, message, Open with password link to Phase 15).
  - **Missing thumbnails** (file path, Regenerate button).
  - **Metadata gaps** (files missing Title/Author/ISBN, link to Phase 07 enrichment).
- Icons: `ic_health_warning` (clay), `ic_health_ok` (sage), `ic_retry` (oak-amber).

### Cross-platform notes

- `Directory.EnumerateFiles` on macOS is case-sensitive; on Windows case-insensitive.
  `DiscoveryService` normalizes paths using `RelativePath` value object from Phase 04.
- SkiaSharp NuGet bundles native `libSkiaSharp` for `win-x64`, `win-arm64`,
  `osx-x64`, `osx-arm64` — no additional bundling required.
- PDFium native binary (Phase 01 spike) bundled for both platforms.
- Avalonia `Dispatcher.UIThread.Post` is the correct cross-platform UI-thread bridge
  (never `Task.Run` + `await` on a view-model directly).

## 13. Risks

| Risk | Tier | Mitigation |
| --- | --- | --- |
| SkiaSharp + PDFium native library version conflict on ARM64 macOS | R4 | Phase 01 spike validates both on Apple Silicon; WP7 blocked until spike is green. |
| Large libraries (10,000+ PDFs) overflow the `Channel<T>` bounded capacity | R3 | Set channel capacity = 500; producer awaits `WriteAsync` (back-pressure); measure throughput with synthetic 10,000-file corpus in perf test. |
| Unavailable-file flagging deletes annotations (regression risk on schema change) | R1 | `UnavailableFileFlagging_PreservesAnnotations` is a required test; EF cascade-delete rules in Phase 04 must not cascade from `BookFiles` to `Annotations`. |
| Per-page thumbnails for 2,000 books × 300 pages = 600,000 files overwhelm the sidecar | R3 | Phase 05 generates only page-0 covers and spines; full per-page thumbnails are on-demand in the reader (Phase 08). |
| `JobRecoveryService` re-queues duplicate jobs if app crashes between job completion and `Status=Completed` write | R4 | Idempotency key prevents duplicate `Books` rows; the worst case is a redundant thumbnail rewrite (safe); documented in ADR. |
