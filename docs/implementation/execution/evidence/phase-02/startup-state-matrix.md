# Phase 2 startup state and interaction matrix

This matrix applies the Ogma design doctrine's state-parity, accessibility and
recovery rules to startup. Screenshots are generated by the headless UI tests in
`artifacts/screenshots/` and are evidence artifacts, not hand-built mockups.

| State | Trigger | Library surface | Primary message | Actions | Focus/live behavior | Recovery |
| --- | --- | --- | --- | --- | --- | --- |
| Bootstrap | Window assigned; composition not yet complete | Hidden | Preparing your library | None | Polite live region; indeterminate progress has an accessible name | Automatic transition |
| Fast startup | Work completes before runtime loading delay | Hidden until safe | No avoidable spinner flash after runtime VM takes over | None | No focus theft | Automatic transition |
| Ready | Required tasks pass; shell initialization completes | Visible | Normal catalogue status | Normal shell actions | Normal shell focus order | Not applicable |
| Optional task failure | Migration passes; recovery/worker task fails | Visible | Ogma started with limited capabilities | Retry startup; export diagnostics | Recovery panel is assertive; retry receives focus after bindings settle | Retry through idempotent tasks |
| Capability unavailable | Local prerequisite absent | Visible when required tasks pass | Capability-specific safe summary | Retry startup; export diagnostics | Unavailable capability is listed; panel is never empty | Restore prerequisite then retry |
| Required migration failure | Catalogue cannot be opened safely | Hidden | Ogma could not finish startup; PDFs unchanged | Retry startup; export diagnostics | Retry receives keyboard focus; assertive live region | Correct transient condition and retry; no PDF mutation |
| Invalid composition/configuration | Options or graph cannot load | Hidden | Application services could not be loaded safely | Correct settings and restart | Assertive failure copy; actions disabled because no safe runtime exists | Fail closed and restart |
| Retry running | User activates retry | Hidden unless prior catalogue was already safe | Preparing your library | Actions temporarily disabled | Polite progress announcement; no duplicate invocation | Cancellable and serialized |
| Diagnostic export succeeds/fails | User activates export | Unchanged | Safe success/failure status | Retry/export remain available as appropriate | Polite live status update | Export can be repeated |
| Shutdown during startup | Application lifetime cancellation | No new state | None | None | Cancellation is not announced as a failure | Started services stop in reverse order |

## Visual verification

- `startup-bootstrap-en.png`: catalogue fully hidden; centered, token-backed
  preparation card; no private paths or technical exception text.
- `startup-degraded-en.png`: blocked catalogue; persistent recovery panel;
  required and unavailable capability issues remain distinguishable.
- `startup-partial-en.png`: catalogue remains first-class beside a persistent
  optional-failure recovery panel.

All action targets are at least 40 pixels high. Loading and recovery surfaces use
existing Ogma color, type, spacing and radius tokens. No motion is required, so
reduced-motion users receive equivalent information without a separate branch.
